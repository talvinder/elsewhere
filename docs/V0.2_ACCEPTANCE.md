# v0.2 acceptance evidence

Azure Container Instances. Every dispatch returned before lifecycle acceptance was
performed. A later refresh reconstructed the job from durable local state, recovered
the exact stdout, exit code, and requested file, verified the result-bundle checksum,
then deleted and verified absence of compute and the result artifact.

The measured matrix is seven Fly runs and three Azure runs. A later Azure batch hit
a public-container-registry `RegistryErrorResponse`; Elsewhere classified it as
retryable, created no compute, and verified each prepared result artifact absent.
Those failed submissions are not included in the ten successful runs.

After the pre-landing fixes, an extra Fly run passed the same exact-result and
verified-cleanup path. Azure's public registry was still returning the transient
error; three safe retries created no retained compute or artifact. The extra smoke
is not included in the ten-row gate above.

Acceptance surfaced and fixed four issues before release: portable BusyBox timeout
syntax, Fly's job-scoped stopped/exit evidence, Azure's transient null
`instanceView`, and cleanup after a pre-compute submission failure. At the end of
the matrix, the local ledger contained zero recent acceptance jobs outside the
`cleaned` state.

Reproduce a non-billable review of the matrix:

```sh
python3 scripts/v02_acceptance.py --runs-per-provider 4
```

receipt. Review the displayed provider count and maximum estimated cost first.
